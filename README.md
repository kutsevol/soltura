# Soltura

A personal Spanish tutor that trains **all four skills** (reading, writing, listening, speaking) together with grammar and verb conjugation. It is not a Duolingo clone: less tapping, more real use of the language.

**Target user (v1):** an adult Ukrainian-speaking learner at A2 level who lives in Spain and wants to reach B1 and beyond.

**Core idea:** one shared **learner model** (words, grammar, mistakes, memory state) feeds every module. A word met in a text comes back in audio, writing and dialogue.

> **Status:** stage 1 (the MVP) is built: the learner model, FSRS review, reading with adaptation and word saving, the recall warm-up and a placement test, behind one app shell. It opens in a browser with a development login; the Telegram Mini App login is the next piece. The later stages below are described but not started.

## Principles

| Principle | Source | How we apply it |
|---|---|---|
| Balance of four strands: input, output, language focus, fluency | Paul Nation, "four strands" | Every session contains all four in roughly equal parts |
| Explicit grammar works, if short and in context | Norris & Ortega 2000; Spada & Tomita 2010 | Short explanations followed by immediate practice, focus on form |
| Train pronunciation from day one | Saito meta-analyses; HVPT | Perception training with varied voices first, then production |
| Text should be 95-98% understandable | Hu & Nation 2000 | Adapt texts to the learner's level |
| Spaced repetition | Cepeda et al. 2006 | FSRS for every learning unit |
| Retrieval beats rereading | Roediger & Karpicke 2006 | Active recall at the start of each session |
| Interleaving | Interleaving research | Mixed review queues |

## Learner model

The single source of truth about the learner:

- **Vocabulary:** the word (lemma), the contexts it appeared in, and a separate memory state per knowledge type (recognize / recall / hear / say).
- **Grammar:** items from the PCIC grammar inventory and their mastery state.
- **Conjugation:** unit = verb x tense x person, grouped by irregularity patterns.
- **Mistakes:** an error log classified by PCIC items.
- **Level and progress:** a level per skill (reading may be B1 while speaking is A2) and completed CEFR can-do descriptors.

## Modules

| Module | What it does | Status |
|---|---|---|
| **Reading** | Adapts real texts (news, everyday letters, posts) to the learner's level at 95-98% coverage. Saves words together with the context sentence. Comprehension questions answered in the learner's own words. | Adaptation, tapping a word to see and save it, and topics are built; comprehension questions are not. |
| **Writing** | A daily journal with corrections (diff and error type). Everyday tasks: a letter to a landlord, a complaint, a note to a neighbour. Mistakes become personal exercises. | Not started. |
| **Listening** | Dictation (audio, typing, comparison), adjustable speed, minimal pairs, varied accents (Spain and Latin America). | Not started. |
| **Speaking** | Voice role-plays (STT, LLM, TTS): doctor, bank, gestoria, bar. Retelling what was read or heard. Pronunciation check via transcription. Shadowing with recording. | Not started. |
| **Grammar** | PCIC-based skeleton by level. Short explanation, recognition in text, gap-fill, free use. Extra focus on topics hard for Ukrainian speakers: articles, ser/estar, gender, indefinido/imperfecto, por/para, subjuntivo. | Not started. |
| **Conjugation** | Forms are generated by **code, not an LLM** (`verbecc` / `mlconjug3`, cross-checked against RAE tables). Practice in sentences, prioritized by frequency. | Not started. |
| **Repetition (SRS)** | **FSRS** algorithm (`py-fsrs`). Every review in a fresh context. Correct use of a word in a text, dialogue or writing counts as a review. | FSRS with a fresh context per review is built; implicit reviews arrive with writing and dialogues. |

## Session structure

1. **Recall warm-up** (2-3 min): the FSRS queue.
2. **Input:** a text or audio at the learner's level, containing units due for review.
3. **Language focus:** a short grammar or phonetics insert tied to the input.
4. **Output:** writing or speaking on the topic of the input.
5. **Fluency:** quick work on already familiar material.

## Assessment and motivation

- Every session: small checks without grades.
- Every 4-6 weeks: a DELE-format checkpoint across all four skills; the result rebalances the plan.
- Instead of XP: progress in CEFR can-do descriptors, a weekly goal instead of a punishing daily streak, a vocabulary coverage map, real-life missions.

## Architecture

- **Backend:** Python, FastAPI.
- **Orchestration:** LangGraph. The orchestrator holds the learner model and plans the session; sub-agents own the modules. The MVP runs the warm-up and reading as plain service calls; LangGraph arrives with speaking, where dialogues need state and branching.
- **LLM:** Claude through the `anthropic` SDK; the model is set with `LLM_MODEL`.
- **Database:** Postgres (learner model, content, error log, FSRS state).
- **Speech:** Whisper (STT), TTS with Spanish voices.
- **Deterministic components:** conjugation, FSRS, text coverage calculation. No LLM involved.
- **Client:** server-rendered pages (Jinja templates, htmx, Pico CSS) that open in a browser and, next, inside Telegram as a Mini App.

## Content and sources

Curriculum and frequency: Instituto Cervantes PCIC, RAE corpora (CREA, CORPES XXI). Sentences and dictionary: Tatoeba, Wiktionary (licenses to be verified). Voices: Mozilla Common Voice. Exam format: DELE/SIELE samples. Main content is generated by an LLM from PCIC topics and the units in the learner's queue.

We do not copy protected textbook, podcast or article content: real materials are linked, adapted versions are generated.

In use today:

- Word frequencies: [wordfreq](https://github.com/rspeer/wordfreq) by Robyn Speer, data under [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).
- Lemmas and part-of-speech tags: spaCy's [`es_core_news_md`](https://github.com/explosion/spacy-models) model, GPL-3.0 (trained on AnCora); it runs only on the server and is not distributed.

## Roadmap

1. **MVP:** learner model, FSRS, reading with adaptation and word saving, recall warm-up. Built, except the Telegram login.
2. **Writing and grammar:** journal with corrections, error log, grammar module, conjugation trainer.
3. **Audio:** dictation, TTS, perception training.
4. **Speaking:** voice dialogues, retelling, pronunciation check.
5. **Assessment and progress:** DELE-format checkpoints, can-do descriptors, coverage map.

## Decisions made

- **Client:** a Telegram Mini App; the same pages also open in a browser.
- **LLM:** Claude through the `anthropic` SDK.
- **Placement:** a short translation test (about 40 words from 8 frequency bands) instead of the first few sessions.
- **Users:** one learner for now, with every table carrying a learner id.

## Open questions

- Choice of TTS and STT (Spanish voice quality, cost).
- Pronunciation assessment: is transcription enough or do we need phoneme-level scoring?
- Does live microphone input work inside the Telegram Mini App on iOS and Android?
- Where to host it.

## Development

Requirements: Python 3.12, [uv](https://docs.astral.sh/uv/), Docker.

```bash
make install            # dependencies and pre-commit hooks
cp .env.example .env    # then set ANTHROPIC_API_KEY
make up                 # local Postgres on port 5433
make migrate
make seed-lexemes       # ranked Spanish lemmas the placement test and text coverage use
make run                # http://localhost:8000
```

In a plain browser the app acts as the learner named by `AUTH_DEV_TELEGRAM_USER_ID` in `.env`.

`make test` runs the suite against a throwaway Postgres container, so it needs Docker but not `make up`. `make help` lists every command.
